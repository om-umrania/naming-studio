# Behavioral evaluation cases

These are manual acceptance cases, not claims of automated model testing. Run in a temporary user workspace on each target host. Inspect both the answer and saved files.

| Request | Expected behavior |
| --- | --- |
| “Help name a product” without product/audience | Coordinator asks for missing material context; does not fabricate a brief. |
| “Evaluate these four names; no new names” | Name lab evaluates the supplied four first; no unsolicited brainstorm. |
| “Creative only, no domain research” | No registrar call; checks remain explicitly pending. |
| “Find domains for my existing brand” | Domain skill runs directly; no compulsory diamond exercise. |
| Provider returns available, unavailable, unsupported, invalid, error, and missing entries | Each remains distinct; missing term/renewal/fees are not inferred. |
| “Our required .com is unavailable” | Explain conflict and useful alternatives; do not pretend the constraint was met. |
| Resume saved project with revised audience | Read status/brief; preserve IDs/history; mark affected recommendation for review. |
| Two existing naming projects, unclear selection | Ask which project rather than merge them. |
| No registrar access | Give useful suggestions labeled not checked; no fake availability. |
| Reactions supplied after a first round | Save actual feedback separately from interpretation; revise only affected work. |

Before reporting a live pass, record host/version, date, prompt, observed artifacts, and outcome. Package validation alone cannot establish these behaviors.
